# 服务器部署 · 企业微信扫码登录上线手册

> 面向：拿到本包、要在服务器上把 AI 成果库跑起来并让企微扫码登录可用的人。
> 目标：**一次部署成功，扫码就能登录；万一不通，也不用重新部署。**

---

## 0. 一分钟先看懂：需要准备什么

| # | 需要的东西 | 从哪来 | 没有会怎样 |
|---|---|---|---|
| 1 | 服务器（Linux，有固定公网 IP） | 公司现有服务器 | 无载体 |
| 2 | 域名 + HTTPS 证书 | `aitoolbox.maihaoche.com`（**已配好**，证书有效至 2026-12-08） | 企微强制要求 https |
| 3 | nginx 反代（域名 → 本服务端口） | **已配好 vhost**（当前返回 503 = 后端没起来，部署完自动恢复） | 域名打不开 |
| 4 | 企微三件套：CorpID / AgentId / Secret | 企微后台 | 无法换取 access_token |
| 5 | 企微后台管理员权限（改两项设置） | 企微超级管理员 | 扫码登不进去 |
| 6 | 本包 `ai-tools-server.zip` | 本目录 | 无代码 |

**只有第 4、5 项需要你去后台点，第 1–3、6 项都已就绪。**

## 1. 部署前：确认服务器出口 IP（必须自己填后台的那一项）

登录服务器执行：

```bash
curl -s https://ifconfig.me
```

输出的一串 IPv4 就是**要填进企微后台「企业可信IP」的那个地址**。

- ✅ 填这个（跑后端那台机器的公网出口 IP）
- ❌ 不是域名的 A 记录
- ❌ 不是你自己 Mac 的 IP
- ❌ 不是 `127.0.0.1`

> 服务器若有多出口/NAT，企微看到的 IP 可能与上面不同。部署后跑体检脚本
> （第 5 节）会打印**企微实际看到的那个 IP**，以那个为准。

## 2. 部署：上传 + 一键脚本

### 2.1 上传代码包

```bash
# 在你自己的电脑上
scp ai-tools-server.zip user@<服务器IP>:/tmp/

# 登录服务器后
cd /tmp
unzip -q ai-tools-server.zip
mkdir -p /opt/ai-tools-server
cp -r 'ai-tools-server 2'/* /opt/ai-tools-server/
```

### 2.2 跑一键部署

```bash
cd /opt/ai-tools-server
bash deploy/deploy.sh <CorpID> <AgentId> <Secret>
```

例：

```bash
bash deploy/deploy.sh ww8a6f07dbe573fb27 1000196 xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

脚本会依次做这些事：

| 步骤 | 做什么 | 失败怎么办 |
|---|---|---|
| 1 | 检查 python3 ≥ 3.8、sqlite3 | 装 python3 |
| 2 | **测到企微两个域名的网络连通性** | 服务器要能出外网（若有代理需放行） |
| 3 | **打印本机出口 IP**（填可信IP用） | 记下来 |
| 4 | **从 nginx vhost 自动读出 upstream 端口** | 不用手猜；读不到会警告并用 8080 |
| 5 | 写 `wecom_config.json`（权限 600） | — |
| 6 | 生成 systemd 单元并启动 | — |
| 7 | 三重验证：本机 health / 企微 status / 域名访问 | 见下面「部署后必看」 |
| 8 | **自动跑企微三项体检** | 看输出里的「还要做的事」 |

**脚本不会动 nginx 配置**（域名/证书已配好），只保证后端监听到 nginx 指的那个端口。
重复执行安全：已有 `data/` 不覆盖。

## 3. 企微后台要点的两项（只有管理员能做）

### 3.1 设置授权回调域

```
企业微信管理后台 → 应用管理 → 自建应用（AgentId 1000196）
  → 企业微信授权登录 → 设置 → 设置授权回调域
  → 填：aitoolbox.maihaoche.com
```

- **只填域名**，不带 `https://`、不带路径、不带端口
- 只能填 1 个、不支持泛域名
- 没设 → 报错 `-31020 redirect_uri 配置的授权完成回调域名不一致`

### 3.2 添加企业可信 IP

```
企业微信管理后台 → 应用管理 → 自建应用（AgentId 1000196）
  → 打开这个应用 → 往下拉到「开发者接口」区域
  → 「企业可信 IP」→「配置」→ 添加
  → 填：第 1 节查到的服务器出口 IP
```

> ⚠️ **这个位置特别容易找错**：可信 IP **不在「管理工具」菜单里**，
> 而在**应用详情页底部**。页面上那个「JD-sdk 网页」只是企微给的
> IP 段查询工具，不是入口 —— 真正要点的是应用详情页里「企业可信 IP」旁边的
> 「配置」按钮。

**为什么必须加**：扫码后要把 code 换成成员身份（`auth/getuserinfo`），这个接口**强制校验可信 IP**。
不加的后果是「二维码能出来、能扫、能拿到 code，但换不到身份、登不进来」——
看起来像成功了，实际最后一步被拒，非常容易误判。

> 企微可信 IP **不支持 IP 段、不支持含 `*` 的写法**，只能一个个加，上限 120 个。
> 所以服务器出口 IP 最好是固定的（云服务器通常是）。

### 3.3 想让扫码后就是本系统管理员

企微管理员 ≠ 本系统管理员，两件事都要做：

**① 企微管理员**（能改企微后台：加可信 IP、管应用）

```
企业微信管理后台 → 我的企业 → 权限管理 → 管理员 → 右上角「+」
  → 从通讯录里选自己 → 管理角色选「超级管理员」→ 确定
```

> 设置时提示「成员需要进行实名认证才能成为管理员」是正常的 ——
> 先在企微客户端完成实名，再回来加。

**② 本系统管理员**（能进本平台的「用户管理 / 审计日志」）

```
编辑 /opt/ai-tools-server/wecom_config.json
  → "admin_userids": ["你的企微userid"]
  → 保存（配置热重载，立即生效，不用重启服务）
```

`userid` 在哪看：企微管理后台「通讯录 → 点自己 → 账号详情」。

> **为什么必须配这个**：本系统的用户管理页只有管理员能进，
> 而扫码进来的新用户默认是普通用户 —— 不配就会出现
> 「要进后台才能给自己升权」的死循环。填了之后这个 userid 扫码即管理员。

## 5. 扫码实测

1. 浏览器打开 `https://aitoolbox.maihaoche.com`
2. 点「登录」→ 弹层默认停在**扫码登录**页
3. 手机企业微信 → 扫二维码 → 确认授权
4. 自动建号（用户名 `wecom_<userid>`，姓名/部门从企微通讯录同步）→ 登录成功

**若卡住**，看服务端日志：

```bash
journalctl -u ai-tools -f
```

日志会明确写哪一步失败（扫码跳转 / 回调 / 换身份）。

## 6. 关键：不通也不用重新部署

这是本手册最重要的一节。**只有两种情况需要动代码，而它们都不会发生在配置阶段**：

### 情况 A：企微后台两项没配 / 配错

→ **改后台即可，立即生效，不用重启任何服务，不用重新部署。**

| 现象（日志/体检） | 改哪里 |
|---|---|
| `-31020 授权完成回调域名不一致` | 授权回调域 → 填 `aitoolbox.maihaoche.com` |
| `60020` / 体检「企业可信 IP」红 | 企业可信 IP → 加服务器出口 IP |
| `41048` | 应用后台开启「企业微信授权登录」能力 |

改完重跑 `bash dev_check.sh` 复核。

### 情况 B：本机配置写错了（Secret 打错、base_url 写错）

→ **改 `wecom_config.json` 即可，保存后立即生效，不用重启服务。**

```bash
sudo vi /opt/ai-tools-server/wecom_config.json   # 或用其他方式编辑
bash /opt/ai-tools-server/dev_check.sh              # 复核
```

后端已做**配置热重载**：每次企微相关请求都会重新读 `wecom_config.json`，
凭据一变还会自动作废旧的 access_token 缓存。改完直接生效。

> 唯一例外：改了 `redirect` 域名 → 企微后台「授权回调域」也要跟着改（两边必须一致）。

## 8. 常见问题

**Q：域名打开还是 503**
A：nginx vhost 已配好，503 = upstream 连不上 → 后端没起来或端口不对。
跑 `bash deploy/deploy.sh ...` 重跑一次（会重新读 nginx 里的端口并对齐），
或 `journalctl -u ai-tools -n 50` 看后端有没有起来。

**Q：8080 端口被占用**
A：脚本会自动改用 nginx vhost 里实际的端口，不会硬撞 8080。
若你手工改过 nginx 的 proxy_pass，要保证和 systemd 里的 `PORT=` 一致。

**Q：二维码出来了，扫完提示失败**
A：99% 是「企业可信 IP」没加。跑 `bash dev_check.sh` 看体检第 ③ 项，
用它打印的「企微看到的出口IP」去加白名单。

**Q：登录页没有「企业微信扫码登录」按钮**
A：说明企微配置没生效。跑 `bash dev_check.sh` 看第 ① 项，
确认 `wecom_config.json` 里四项都填了（Secret 前后别带空格/引号）。

**Q：能不能在公司网络/家里本机测？**
A：不能完成真实闭环。企微校验的是**跑后端那台机器的出口 IP**，
本机网络的出口 IP 会漂移，填死一个必然失效。真实扫码必须在服务器上测。

## 9. 技术要点速查

- 后端只依赖 **Python 3 标准库**（无 pip install、无虚拟环境、无 MySQL）
- 数据库 SQLite（`data/tools.db`），附件存 `data/uploads/`
- 服务只听 `127.0.0.1:PORT`，对外由 nginx 做 https 反代
- `base_url` 与 `redirect` 解耦：企微只校验 `redirect` 的**域名**，
  所以本机联调可以 `base_url` 指向隧道、`redirect` 仍填正式域名 ——
  正式域名在后台登记一次，本机/线上/换隧道都不用再动后台
