# 工具库页面 · 后端接口契约（对接文档）

> 给后端 / 运维同事。前端页面 `demo4-卡片风滚动分页.html` 已就绪，所有数据当前为前端演示态（`USE_REAL_API=false`，写入内存、刷新即重置）。本契约描述接入真实后端后需要实现的接口与数据模型。
>
> **需求定案（已拍板，勿再当选项）**：不做登录接入 → 点赞 / 收藏为**全局计数器、可连点、无取消、无逐人去重** → **不需要** `user↔tool` 关系表。

---

## 1. 设计前提

| 项 | 结论 |
|---|---|
| 登录 | 不接入 |
| 点赞 | 全局整数，连点无上限、不取消 |
| 收藏 | **不做**——没有登录态就无法区分"谁收藏了"，收藏入口已按产品决定移除（曾短暂加回后被要求撤掉） |
| 关系表 | 不需要（无 user 维度） |
| 计数器防刷 | 本期不做；内部展示页，接受可被连点刷高 |

> 数据库里仍保留 `favorites` 整数列与 `POST /api/tools/{id}/favorite` 接口，**当前前端不会调用**——留给将来接入登录态后直接启用，避免届时改表。

前端展示字段、标签分类、分页规则已固定，后端只需返回对应结构。

---

## 2. 数据模型

### 2.1 `tools` 表（工具主表）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint / string | 主键，全局唯一 |
| `name` | string | 工具名称 |
| `dept` | string | 所属部门 |
| `type` | enum | `智能体` / `内容生成` / `效率工具` / `数据自动化` / `其他` |
| `desc` | string | 一句话说明 |
| `detail` | json | `{ intro:string, usage:string[], highlights:string[] }` 详情页内容 |
| `link` | string? | 入口链接（选填，可为空） |
| `files` | json[] | 附件列表（见 2.2，可空） |
| `added_at` | date | 上架日期 `YYYY-MM-DD` |
| `is_new` | bool | 是否新上架（前端标记用） |
| `downloads` | int | 累计下载数，默认 0 |
| `likes` | int | 累计点赞数，默认 0 |
| `favorites` | int | 累计收藏数，默认 0 |

### 2.2 `files` 表（附件）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint / string | 主键 |
| `tool_id` | ref | 关联 `tools.id` |
| `name` | string | 文件名 |
| `size` | int | 字节数 |
| `type` | string | MIME / 扩展名 |
| `url` | string | 可访问下载地址（对象存储或服务器路径） |

> 二进制本体存对象存储（COS/OSS）或服务器磁盘；数据库只存 `url`。

---

## 3. 接口清单

基础路径：`/api`。所有写接口返回 JSON：`{ "ok": true, "data": ... }`；失败返回 HTTP 4xx/5xx + `{ "ok": false, "msg": "..." }`。

### 3.1 列表 `GET /api/tools`
查询参数（均选填）：
- `q`：关键词，模糊匹配 `name`/`dept`/`type`/`desc`
- `tag`：标签，值取自上面 enum（空或 `全部` = 不过滤）
- `page` / `pageSize`：分页参数。**不传 `page` = 返回全量**（前端自己做搜索/筛选/分页，所以它不传）；传了才分页（默认 page=1、pageSize=12）

响应：
```json
{
  "ok": true,
  "data": {
    "total": 28,
    "page": 1,
    "pageSize": 12,
    "items": [
      {
        "id": 1,
        "name": "周报生成器",
        "dept": "经营管理中心",
        "type": "效率工具",
        "desc": "粘贴零散记录，自动生成结构化周报",
        "detail": {
          "intro": "…",
          "usage": ["步骤1", "步骤2"],
          "highlights": ["亮点1", "亮点2"]
        },
        "link": null,
        "files": [{ "name": "使用说明.pdf", "size": 12345, "type": "application/pdf", "url": "https://…/x.pdf" }],
        "addedAt": "2026-10-18",
        "isNew": false,
        "downloads": 2100,
        "likes": 186,
        "favorites": 42
      }
    ]
  }
}
```

### 3.2 上传附件 `POST /api/upload`
- 请求：`multipart/form-data`，字段 `file`（可多文件）
- 响应：`{ "ok": true, "data": [ { "name", "size", "type", "url" } ] }`
- 把二进制落地后返回可下载 `url`，前端用这个 `url` 填进 3.3 的 `files`

### 3.3 创建工具 `POST /api/tools`
- 请求：`application/json`
```json
{
  "name": "演示新工具",
  "dept": "经营管理中心",
  "type": "效率工具",
  "desc": "（发布者还没有填写说明）",
  "link": null,
  "files": [ { "name": "使用说明.pdf", "size": 12345, "type": "application/pdf", "url": "https://…/x.pdf" } ],
  "detail": { "intro": "…", "usage": ["…"], "highlights": ["…"] }
}
```
- 响应：`{ "ok": true, "data": { "id": 29, ...完整工具对象 } }`
- 后端自填 `added_at=今天`、`is_new=true`、`downloads/likes/favorites=0`

### 3.4 下载 `GET {files[].url}`
- 由 3.1 返回的 `url` 直接下载；前端拿到文件后调 3.5 累加计数
- 二进制走存储/CDN，不走此 JSON 接口

### 3.5 计数自增（点赞 / 收藏 / 下载）
三个接口结构一致，均为 `+1`：
- `POST /api/tools/:id/like` → `likes += 1`
- `POST /api/tools/:id/favorite` → `favorites += 1`
- `POST /api/tools/:id/download` → `downloads += 1`

响应：`{ "ok": true, "data": { "likes": 187 } }`（返回自增后的值）
- 无去重、无上限、无取消（按需求定案）
- 必须用**数据库层原子自增**（`UPDATE tools SET likes = likes + 1`），不能"先读再+1再写"，否则并发会丢计数
- 失败静默忽略即可，不影响前端交互

### 3.6 健康检查 `GET /api/health`
响应：`{ "ok": true, "data": { "status": "ok", "tools": 28, "uptime_sec": 3600, "db": "...", "data_dir": "..." } }`
用于运维探活与监控接入。

## 4. 前端对接改动点（已实装，参照 `ai-tools-server/web/index.html`）

1. `USE_REAL_API` 改为 `true`；新增 `API_ON` 开关——**只有用 http(s) 打开才连后端**，直接双击打开 HTML（file://）仍是纯前端演示态、零网络请求（单文件分发不受影响）。
2. **列表**：启动时 `loadToolsFromApi()` 调 `GET /api/tools`（不传 page → 全量）覆盖内置演示数据；失败则继续用内置数据，页面不崩。搜索/标签/分页仍由前端做，所以后端返回全量。
3. **上传**：先 `POST /api/upload`（FormData，字段名 `file`）拿回 `url`，再 `POST /api/tools` 提交带 `url` 的 `files`；成功后用后端返回的正式记录（真实 id/addedAt/附件 url）插到列表最前，**上传后立刻可见**，不必刷新。
4. **下载**：已有 `f.url` 分支可直接用真 `url`；下载成功后调 3.5 累加计数。
5. **点赞 / 收藏**：`t.likes` / `t.favorites` 改为调 3.5 并回写返回值；`t.liked` / `t.saved`（红心/星标填充态）降级为**纯前端展示**（无登录无法持久化"我点没点过"，刷新即重置），保留点击动效但不做持久切换。
6. **收藏不做**：原页面无收藏入口，产品已明确「没有登录状态的收藏没有实际意义」，**不提供收藏按钮**（工具卡与详情页都只有 点赞 / 下载）。后端字段与接口预留但不被调用。
7. **种子数据**：当前是 **9 个真实工具**（`seed/seed_tools.json`），`downloads`/`likes` 已**归零**，作为真实计数起点；不是演示占位值。

## 5. 部署侧（运维）
- 前端：单 HTML 文件，静态托管即可（见部署说明）。
- 后端：需一台能跑服务 + 数据库（SQLite / MySQL / PG 均可，本契约与具体选型无关）+ 文件存储。
- 跨域：前端同源部署则无 CORS；若前后端分域，后端需放开对应 `Origin` 的 CORS。
